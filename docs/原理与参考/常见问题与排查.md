# 常见问题与排查

从问题出现的阶段开始检查。报告问题时记录客户端编号、发生时间、访问的业务路径及错误提示，截图和日志中的授权码、校验值、客户端密钥和令牌应遮盖。

| 现象 | 核对方法 |
| --- | --- |
| 示例启动不了 | 检查 Java、Maven、Node.js 是否安装，终端能否访问依赖仓库，以及 18085 或 5173 是否被占用 |
| 首页能打开，业务页提示配置缺失 | 核对 `.env` 位置、同名进程变量是否覆盖文件，以及密钥是否已替换为平台交付的值。修改后重启示例 |
| 跳转到认证地址后无法访问 | 检查 `SSO_BASE_URL` 是否填成了公共认证接口前缀，以及浏览器和客户端后端是否均可访问 |
| 平台提示客户端或回调无效 | 将平台登记、客户端配置和浏览器实际访问地址逐项比对，尤其检查协议、主机、端口和路径 |
| 提示登录事务不存在、过期或已使用 | 从业务页发起一次新登录，核对回调是否沿用了发起时的客户端入口、会话是否仍在，以及回调是否被重复打开 |
| 登录后回到错误端口或出现 404 | 核对登记地址与代理路由，以及回调后的业务路径是否到达原客户端。使用开发代理时，浏览器入口和回调都使用 5173 |
| 页面受控返回无权限 | 核对两端认证模式、页面编码和真实路径，再核对测试账号所属角色和平台登记的权限项 |
| 平台维护绑定时返回无权限 | 从平台授权阶段拒绝时先查当前用户在该客户端的绑定。回调已得到用户资料时，再查两端必绑开关是否配套、`externalUserId` 是否读取成功以及本地账号是否启用。示例中的 `108` 已启用，`109` 已停用 |
| 页面放行，但业务接口拒绝 | 核对接口对本地角色、数据范围或页面授权的检查。先确认账号，再确认这条业务权限 |
| 全局退出未完成或退出后回到错误地址 | 检查浏览器是否已经跳转到平台退出入口，以及平台登记和退出回跳的协议、主机及端口是否一致 |
| 本地退出后再次进入没有看到登录页 | 查看是否只退出了本客户端。平台仍处于登录状态时，可以为当前客户端重新授权 |
| 本地提交请求返回 403 | 核对是否携带同一个本地会话的 CSRF 校验值（用于确认提交来自当前站点）。示例细节见[前端调用参考](示例前端调用参考.md) |

若要定性判断问题发生在哪一段，可在浏览器的“网络”面板顺序观察业务入口、平台授权、固定回调与最终页面，再对照客户端后端的同一时段日志。回调地址中的一次性参数用完即失效，复查应从原业务入口开始。
