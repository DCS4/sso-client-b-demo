# 配置、密钥与访问地址

## 配置文件放在哪里

复制仓库根目录的 `.env.example` 并编辑 `.env`。它按 `键=值` 格式读取。启动进程从当前目录或上一级目录尝试加载该文件。通常把它放在仓库根目录，部署单个 Java 应用包时则放在启动命令所在的部署目录。每套运行环境保留一份，修改后重启后端。也可以通过同名进程环境变量注入配置。如果两处都设置了同一个变量，以启动进程的环境变量为准。修改文件后仍看到旧配置时，请检查进程环境。

| 配置项 | 示例默认值 | 使用时填写 |
| --- | --- | --- |
| `SSO_BASE_URL` | `http://localhost:19089/oauth2Server/oauth2` | 平台管理员提供的公共认证接口前缀。示例的浏览器授权和后端接口调用均使用它 |
| `SSO_CLIENT_ID` | `demo_client_b` | 平台登记后交付的客户端编号。默认编号只是示例 |
| `SSO_CLIENT_SECRET` | 空 | 平台管理员交付的明文密钥 |
| `B_CALLBACK_URL` | `http://localhost:18085/api/auth/callback` | 浏览器可访问的完整回调地址，须与登记组合一致 |
| `SSO_AUTH_MODE` | `PAGE_CONTROLLED` | 与平台选择一致。页面受控用 `PAGE_CONTROLLED`，普通单点登录用 `SSO_ONLY` |
| `SSO_REQUIRE_EXTERNAL_ACCOUNT` | `false` | 平台维护账号绑定时设为 `true`，同时选择普通单点登录并在平台启用必绑 |
| `SERVER_PORT` | `18085` | 后端监听端口 |
| `COOKIE_SECURE` | `false` | 本机 HTTP 使用 `false`，浏览器通过 HTTPS 访问时使用 `true` |
| `SSO_CONNECT_TIMEOUT` / `SSO_READ_TIMEOUT` | `2s` / `3s` | 后端连接平台和等待响应的超时 |

外部账号对应关系由平台侧管理。要在示例中走完绑定登录，平台开启必绑后，示例填写 `SSO_AUTH_MODE=SSO_ONLY` 和 `SSO_REQUIRE_EXTERNAL_ACCOUNT=true`。示例配置用于要求回调检查本地账号。默认本地会话保留 30 分钟，使用 `B_DEMO_SESSION` 作为浏览器会话标识。

## 客户端密钥由谁保管

平台管理员在创建客户端或重置密钥时取得一次性展示的明文。通过约定渠道交给接入方的后端负责人，填入 `SSO_CLIENT_SECRET`。平台保存密钥的校验值，接入方调用平台受保护的认证接口时，后端使用明文证明自己的客户端身份。

密钥应保存在后端进程配置或受控的密钥存储中。遗失或需要轮换时，由平台管理员在对应客户端下重置。接入方收到新密钥后更新后端配置并重启，旧密钥立即失效。若管理员通过接口重置，参数中的 `id` 是客户端登记记录的编号。它与发给接入方的 `client_id` 用途不同。

## 浏览器入口、回调和后端监听地址

| 项目 | 单应用包运行 | 前后端分开开发 |
| --- | --- | --- |
| 浏览器打开的示例首页 | `http://localhost:18085` | `http://localhost:5173` |
| 平台登记的系统地址 | `http://localhost:18085` | `http://localhost:5173` |
| 平台登记的固定回调路径 | `/api/auth/callback` | `/api/auth/callback` |
| 配置中的完整回调 | `http://localhost:18085/api/auth/callback` | `http://localhost:5173/api/auth/callback` |
| 后端实际监听 | `http://localhost:18085` | `http://localhost:18085` |

固定回调完整地址由登记的系统地址与回调路径组合而成。浏览器发起登录和返回客户端时应使用同一个客户端入口，便于后端找回登录请求。双进程开发时，前端开发服务器负责把 `/api` 和 `/pages` 转发给后端。后端端口变化时，同步更新 `frontend/vite.config.ts` 中的代理目标。

`localhost` 指访问这个地址的那台机器。若在另一台电脑上打开浏览器，应统一换成它能访问的 IP 或域名，并同步修改平台登记和完整回调。使用反向代理时，登记代理对浏览器提供的地址，代理内部转发至实际后端。浏览器访问代理入口，代理访问实际后端。应分别确认两段网络均可达。

## 浏览器同源和会话标识

浏览器按协议、主机和端口判断网页来源。整页导航可以跨来源，前端脚本读取跨来源接口响应需另外配置。示例把登录流程放在浏览器整页跳转和后端通信中。若需要统一来源，可用反向代理在同一协议、主机和端口下转发路径。仅统一 IP、仍使用不同端口，仍属于不同来源。

会话标识（Cookie）发送范围受域名、路径和安全属性等约束。平台会话和本地会话独立维护。同一对外主机托管多个应用时，应检查名称与发送范围，避免不同应用会话相互覆盖。默认示例按站点根路径运行，使用子路径部署时，应检查静态资源、业务接口、固定回调和退出回跳。
